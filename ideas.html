What this is — and how it ships

What it is: a filtered catalog of software products for guitar players, producers and teachers. It came from a full survey of the guitar app, website and plugin landscape (parts 1–4 of the research), then passed through one hard filter: the €0 rule. If an idea can't be built and launched with zero money, it's not on the live list — it's in the parked table with the reason why.

How it ships — the format, named properly: every live idea is PC software, built in two shapes from one codebase:

  • Web App — open a link in your browser. Nothing to install, works on Windows, macOS and Linux, instant updates, zero distribution cost.
  • Desktop App — install it on your PC. Runs fully offline, keeps your files on your own machine, no server bills for the builder.

Why desktop matters here: guitar software works with audio, and audio belongs on your machine. A local-first desktop app can process stems, practice audio, tabs and recordings without anyone paying for cloud compute — which is exactly how these ideas stay free to build and free to run.

Section 01The €0 rules — how the cut was made

Three rules. An idea survives only if it passes all three. Everything else is parked, not deleted — the parked table tells you exactly what to avoid until money exists.

RULE 1
Build with free tools only.
Open source, free tiers, on-device processing. No paid APIs, no GPU rentals, no paid plugins, no hardware purchases, no sample-library budgets.
RULE 2
Launch with €0.
Free hosting (GitHub Pages, Cloudflare, Vercel free tier), free subdomain. Web/PWA/desktop first — the $99/year app-store accounts and €10 domains can wait until revenue exists.
RULE 3
No licensed content.
Everything the product touches must be: yours, public domain, crowd-sourced, or the user's own files. This single rule kills every copyright problem before it starts.
The plugin extra-rules: build with iPlug2 (MIT) or DPF (ISC) — not commercial JUCE. Ship VST3 + CLAP + LV2, skip AAX. No iLok. CPU inference only (NAM "nano/feather" architectures run on CPU). Capture training via TONE3000's free cloud trainer — never rent a GPU. Distribute from your own page + free storefronts (fees only when you actually sell).

#131 · COLLECTORS & LUTHIERS

Repair Diagnostic Wizard ★ best first project

What it is
A guided troubleshooter for guitar problems. You describe a symptom — "it buzzes on the 7th fret of the G string only when I bend, and only on the low E" — and it walks a decision tree to likely causes (relief, high fret, nut slot, saddle, pickup height, technique), ranked by probability, with a fix order and cost estimates.
Why it's deep
Millions of searches a year for "guitar buzz" alone. The answers exist but are scattered across forums written in 2009 by people arguing. Nobody has structured the knowledge into one calm, correct flow. That's the whole product: structured knowledge, beautifully presented.
How it works
A static site with a branching logic tree + measurement guides (feeler-gauge equivalents using a credit card, ruler, phone camera). Content is written once and refined by user feedback. No backend needed at launch — pure HTML/JS.
Why it's €0
It's content and logic. Hosting on Cloudflare/GitHub Pages free tier. No audio, no licenses, no inventory, no APIs. The single cheapest idea in the bank to build.
Money later
Affiliate links to parts and tools (saddles, files, gauges), paid lead-gen to local luthiers ("matched a repair shop"), a Pro version with saved instrument profiles, and later the luthier-facing tools (#137/#138).
First step
Write the 12 most-searched symptom → cause trees this week. Ship 3 of them. Watch which ones get shared.
#27 · TABS & NOTATION

Public-Domain Songbook Generator ★ legally bulletproof

What it is
A generator that turns public-domain music into beautiful, playable guitar arrangements: tab, standard notation, chord diagrams and audio playback. Feed it a traditional tune, a hymn, a folk song, a classical piece — out comes a clean arrangement a beginner can actually play.
Why it's deep
Every tab site in the world lives under a copyright cloud — most of their content is user transcriptions of protected songs. Public domain is the one pool of music where you can build forever without asking anyone for permission. Thousands of folk songs, hymns, Christmas carols, Renaissance and classical pieces are free to use and re-arrange.
How it works
Sources like Mutopia, IMSLP and old hymnals (all PD) feed a pipeline: parse the tune → arrange for guitar (melody + simple bass/chords, multiple difficulty levels) → render via alphaTab (open-source tab rendering/playback) → synthesize audio with FluidSynth + CC0 soundfonts. All open source, all local.
Why it's €0
PD content + open-source tools + static generation. You literally own the output and can give it away forever.
Money later
Print-on-demand songbooks (no inventory), Pro features (custom arrangements, transposition, difficulty personalization), bulk licensing to teachers and schools (#125/#130).
First step
Pick one category (Christmas carols or fiddle tunes), ship 50 arrangements with audio, publish the generator so people see the engine.
#209 · PLUGINS — CAPTURES

Device-Targeted Capture Optimizer ★ perfect timing

What it is
Tool that takes a NAM (Neural Amp Modeler) capture and whips it into the exact shape a specific piece of hardware needs — Hotone, Valeton, HeadRush, ToneX-class pedals — with a quality report before you load it: fidelity loss, latency footprint, CPU profile, and an A/B preview.
Why it's deep
The NAM ecosystem exploded in 2026: free open-source architecture, 700,000+ captures, and hardware makers rushing to support it (HeadRush, Hotone, Valeton, Blackstar). Every device wants a slightly different variant, and vendors ship one-off converters if anything at all. A cross-device optimizer with quality reporting is the missing middleware — and the wave is happening right now, not in two years.
How it works
NAM is MIT-licensed and the file format is open, so you can parse and re-target captures. Downscale architectures (A2 → "nano"/"feather" variants), normalize levels against a reference DI, and validate by running the model and comparing output statistics. Desktop app (offline, CPU-only).
Why it's €0
Open format, free trainer (TONE3000 cloud), no server needed — processing happens on the user's machine. Distributed free or via free storefronts.
Money later
Pro tier for creators (batch optimization + quality badges), partnerships with pedal makers who want "verified working on our device" content, and a marketplace of validated packs.
First step
Build a CLI that reads a .nam file and outputs the correct downscaled variant for one device. Prove one device end-to-end. Then add the A/B report UI.
#219 · PLUGINS — WORKFLOW

AI-Tab Fidelity Checker ★ rides the AI wave

What it is
A validator for AI-generated guitar tabs and notation. Feed it (a) the audio, (b) the AI's tab output — from Klangio, Songscription, AnthemScore, Melodyne, anything. It scores two things: accuracy (does the tab match the audio note-by-note?) and playability (can a human actually play it — fret spans, position jumps, string choices), then auto-suggests repairs.
Why it's deep
2025–26 flooded the market with AI transcribers. They're fast and impressive and wrong in ways that matter: phantom notes, unplayable stretches, rhythm that doesn't line up. Everyone who uses them needs a check step, and nobody sells one. Being the "spell-check of AI tabs" is a defensible position in a category where the transcribers themselves will never point out their own errors.
How it works
Score the tab against the audio using alignment + pitch/onset comparison (free tools: Basic Pitch, librosa-style analysis). Then apply guitar-logic rules: max fret span per hand size, position-transition costs, string-choice heuristics. Output a per-bar heatmap + suggested fixes. Local desktop app; the user brings their own files.
Why it's €0
User-supplied files (Rule 3 — you never host copyrighted content), open-source analysis, on-device processing.
Money later
Freemium (fixes beyond the first N per song), an API for tab sites and teachers to auto-vet submissions, and teacher bundles.
First step
Take 10 songs where you know the ground truth, run three AI transcribers, and measure how they fail. That failure taxonomy is the product spec.
#89 · BACKING TRACKS

Generated Backing Tracks ★ the flagship

What it is
Type in your chords (or import a chart), pick a style, tempo and feel — out comes a studio-ish backing band: drums, bass, keys, optional rhythm guitar. Count-ins, fills, sections (verse/chorus/bridge), key changes on demand. The user owns the output.
Why it's deep
Everyone practices with backing tracks; almost all of it is either unlicensed (YouTube loops), expensive per-track, or wrong for your song (fixed loops in a random key). Generated-for-you tracks solve all three — and they carry zero copyright exposure, because the audio is made from scratch for this user, not copied from a record.
How it works
Procedural generation: a pattern engine (styles as data), a sample/synthesis layer with free CC0 soundfonts (FluidSynth) or generated drums, chord parsing from charts (ChordPro), and humanization (swing, dynamics, fills). Start with drums + bass + simple keys — that's 90% of practice value. Runs locally in a desktop app or in-browser via Web Audio.
Why it's €0
The whole thing is code + free samples. No AI cloud music model, no per-track API fees, no licenses — you own everything you generate, so the user can too.
Money later
One-time unlock or packs (styles, expansions), teacher/school site licenses, and later a licensed-content marketplace only if you ever want that headache (#91 stays parked).
First step
Ship one style (slow blues or pop ballad) with drums+bass, chord input via text field. Ten loyal users is enough to know.
#194 · PLUGINS — TRANSCRIPTION

Guitar → Tab On Your Own Takes ★ closes a real loop

What it is
You play into your PC (or load a recording you made), and it produces a clean, playable tab of what you actually played — with sensible fret positions, string choices and techniques inferred where it can (slides, bends, palm mutes as "probable"), ready to edit and export.
Why it's deep
All the existing AI transcription tools aim at music from streaming — the copyright minefield — and they output messy, unplayable results. Aiming at the user's own recordings flips both problems: legally clean, and personally useful. Teachers wanting to document a student's progression, composers sketching ideas, players archiving riffs — nobody serves them, because everyone is chasing "transcribe Spotify".
How it works
Spotify's Basic Pitch (Apache-2.0, free, runs on CPU) for note extraction, then your own layer: guitar-logic inference for position/fingering, notation rendering via alphaTab/VexFlow, MIDI export. Desktop app; processing local.
Why it's €0
Free open-source model + local processing + the user's own audio. No rights, no servers, no GPU.
Money later
Pro tier (export formats, batch, precision modes), teacher bundles, an API for practice apps.
First step
Build the pipeline for a single-note melody line, then chords one string-set at a time. Measure output against your own recordings — you're the ideal test user.
#3 + #4 · PRACTICE

Practice Logger + "Guitar Wrapped" ★ the habit machine

What it is
A desktop/web app that passively detects when you're playing (audio activity through your interface/mic), logs sessions automatically, saves your best take of each session, and once a year (or month) shows you a beautiful recap: hours played, streak, most-played keys and tempos, speed progress, before/after clips.
Why it's deep
Every practice app in existence makes you declare your practice (timers, forms). Nobody just notices. And nothing gives guitarists the one thing that spreads products like fire — a shareable, flattering, personal annual recap. Spotify Wrapped taught the entire internet that people love their own data when it's presented well. Guitarists have never had it.
How it works
On-device audio activity detection (simple RMS + musical-content heuristics to avoid counting Netflix), IndexedDB/SQLite for logs, Web Audio for saving take snippets. Web app first (installable PWA), desktop app later for always-on monitoring.
Why it's €0
All processing local. No cloud audio, no storage bill. Static free hosting.
Money later
Freemium: free logging + recap, Pro for insights ("your tempo ceiling rose 12 BPM this quarter"), coaching marketplace connections, teacher dashboards.
First step
Ship the detector alone: "we logged 34 minutes today" is the whole MVP. Then wrap the stats.
#220 · PLUGINS — PORTABILITY

Cross-Vendor Preset Portability Hub ★ community data moat

What it is
Tone is trapped in ecosystems. You build a sound on a Helix, you want it on Quad Cortex or AmpliTube or your friend's Kemper. This hub is (a) a community-maintained map of how parameters correspond between platforms, and (b) a converter assistant that does a best-effort translation and honestly flags what it can't translate.
Why it's deep
Vendor librarian software is deliberately one-device-only. The community already does this by hand in forum threads, badly. Five years of crowd edits later, you own the interchange layer — the thing everyone consults and nobody can clone because it's built on thousands of verified mappings, not code.
How it works
Structured mappings (JSON) per parameter type, community-submitted + moderated; a converter for the easy 80% (gain structure, EQ points, delay/reverb parameters, ordering); export to preset formats where openly documented. Static site + a small local converter app.
Why it's €0
Community content, static hosting, local conversion. No vendor deals needed (they may later come to you).
Money later
Pro conversion packs for complex platforms, brand partnerships, and the standard itself (#202/#226) as an asset.
First step
Publish 20 mappings for the two most popular platforms and let people edit them. The editing UX is the product.
#49 · EAR TRAINING

On-Instrument Ear Trainer ★ the loop nobody closes

What it is
Ear training where the answer is played on your guitar, not guessed with buttons. The app plays a note, interval, scale degree or short phrase; you play it back through your mic or interface; it scores pitch accuracy, timing and consistency. The skill you actually need — ear → hand — trained for real.
Why it's deep
Ear training is a proven paid category (functional ear trainers, interval apps, exam-prep). But virtually all of it is multiple-choice listening on a phone. The gap between "I can recognise a perfect fourth" and "I can play back a melody I hear" is exactly where musicians live, and almost nothing trains it. Training through the instrument also means the app teaches fretboard ear: which position, which string, which octave.
How it works
Web Audio for playback; pitch detection (YIN/autocorrelation or CREPE) on the mic input; scoring engine for pitch/timing; difficulty ladder from single notes → intervals → scale degrees → 2-bar phrases → call-and-response. Browser first, all local.
Why it's €0
Pure DSP in the browser. No content licenses (it plays tones it generates), no server, no hardware.
Money later
Subscription for structured programs and progress stats; teacher licensing (tie to #118/#119); exam-prep packs (tie to #7).
First step
Ship "play back the note" with clean pitch scoring. Nail the microphone experience — that's the moat.
#118 · TEACHING (B2B)

Self-Grading Homework ★ cash before cost

What it is
The teacher assigns a task: "play this chart at 80 BPM, clean chord changes." The student records the attempt in the app. It gets scored automatically — timing vs. the click, chord clarity, missed changes — and the teacher sees a detailed report before the next lesson, including a waveform-level view of the trouble spots.
Why it's deep
Every guitar teacher wastes the first ten minutes of every lesson re-listening to what the student did at home, badly self-reported. This replaces that with data. It's also the classic B2B shape that fits a €0 builder perfectly: the school pays by invoice, so money arrives before you spend anything on infrastructure.
How it works
Browser recording (MediaRecorder), on-device scoring against a reference click + expected chord chart, a teacher dashboard (can start as a free-tier web app), simple accounts. The scoring core is shared with #3/#49/#200 — build once.
Why it's €0
Free-tier hosting + local processing; no licenses (charts are PD or the teacher's own, #125/#130 help there); students never pay, so there's no payment infra to build at the start.
Money later
Schools and teachers pay a flat monthly per-class or per-teacher fee by invoice; later, a marketplace of self-grading assignment packs (scales, exam pieces, technique drills).
First step
One teacher (or yourself as a test) + one assignment type (chord-change timing against a click). Prove the report saves lesson time.
#169 · TRUST & STANDARDS

Open Tab Format + Viewer SDK ★ infrastructure play

What it is
The missing open layer on top of alphaTab: a modern, community-owned tab data format (with techniques, annotations, difficulty levels, licensing metadata per entry) plus an embeddable viewer that any small site, teacher, or forum can drop in with one line of code — free.
Why it's deep
Tab distribution today is either giant ad-choked platforms or PDFs. The rendering technology (alphaTab) is already open and excellent — what's missing is format + metadata + ecosystem: an easy way for independent sites to host playable tabs with clear rights, and for creators to publish with attribution. Whoever provides that plumbing becomes the quiet standard everything else is built on.
How it works
Define the format (JSON-based, versioned), write converters (import from Guitar Pro / MusicXML / text tab, export the same), build the SDK around alphaTab (MPL-2.0 — embedding is fine) with a clean skin, publish everything open source, and run a free CDN-hosted viewer.
Why it's €0
Open source + static/CDN free tier. The work is design and standards, not infrastructure.
Money later
Hosting/analytics/takedown-management services for sites that adopt it, paid annotations (professional transcriptions), and consulting/adapters for schools and publishers.
First step
Ship the viewer + format spec with 20 example public-domain tabs. Get three real sites embedding it — that's adoption, not downloads.
#147 + #148 · SOCIAL

Riff Battles + Daily Riff Streak ★ distribution first

What it is
Two halves of one growth engine. Daily Riff: a new riff lands every day; you record 15 seconds; a streak counter keeps you honest; you can duet anyone else's take. Riff Battles: head-to-head brackets on weekly themes, judged by community votes and an audio score.
Why it's deep
This is the only category in the bank that is distribution-first: content is user-generated (no rights cost), clips ride short-video behavior people already have, and the streak gives the retention mechanics every lesson app wishes it had. Meanwhile the incumbents are all paywalled classrooms — nobody owns the free, social, daily-habit layer for guitar.
How it works
Browser recording (MediaRecorder) → optional on-device audio scoring (shared engine with #3/#49) → free-tier storage for small clips (or user-hosted + embed) → ranking/voting logic. PWA first; everything can start on free tiers because clips are short.
Why it's €0
UGC content + generated riffs (your own, from #89's engine if you like), free static hosting, clips kept tiny. At real scale you'd outgrow free tiers — by then you have users to monetize.
Money later
Brand sponsorships (gear makers want this audience), cosmetic/vanity features, tournaments, and the challenge packs feeding into the practice apps (#3/#25).
First step
Run one week of daily riffs manually (a post per day, replies as entries) before writing any code. If the format catches, build it.

Section 05The €0 stack — every tool verified free

Everything you need to build any idea in this bank, with zero money. Local-first beats cloud every time: it's cheaper to run, faster to ship, and better for audio.

Code & apps

  • Editor: VS Code
  • Version control: Git + GitHub (free private repos, free CI minutes on public repos)
  • Languages: Python, TypeScript/Node, Rust (for WASM)
  • Web framework: SvelteKit / React / Solid + Vite
  • Styling: Tailwind
  • App shape: PWA (installable, offline) + IndexedDB/SQLite = no backend bill

Audio

  • Engine: Web Audio API + AudioWorklet, Tone.js
  • Tabs: alphaTab (MPL-2.0) — render + play Guitar Pro files
  • Notation: VexFlow
  • Theory: Tonal.js
  • Backing tracks: FluidSynth + CC0 soundfonts
  • Transcription: Spotify Basic Pitch (Apache-2.0)
  • Stems: Demucs (MIT) — local, short clips, no cloud GPU
  • Pitch: YIN / CREPE

Plugins & amp tech

  • Frameworks: iPlug2 (MIT) or DPF (ISC) — skip commercial JUCE
  • Formats: VST3 + CLAP + LV2 (skip AAX)
  • Amp modeling: NAM (MIT, CPU inference, "nano/feather" sizes)
  • Capture training: TONE3000 free cloud trainer + free plugin
  • Licensing: simple offline license files — no iLok

Backend, only if truly needed

  • Hosting: Cloudflare Pages/Workers, Vercel, GitHub Pages (free tiers)
  • Database: Supabase / Neon / Turso free tiers
  • Storage: Cloudflare R2 / Backblaze B2 (10 GB free)
  • Email: Resend / Brevo free tiers
  • B2B basics: Google Sheets + Forms for scheduling and invoicing — genuinely fine at the start

Design & marketing

  • Design: Figma free, Inkscape, GIMP, Krita
  • Social assets: Canva free
  • Type: Inter (OFL)
  • Video: OBS — free demos and tutorial clips

Money-in — €0 upfront, fees only on sales

  • Storefronts: Gumroad, itch.io
  • Payments: Stripe Payment Links
  • Tips/support: Ko-fi, GitHub Sponsors, Patreon
  • B2B: invoice directly — no infrastructure required
Free-tier survival rules: local-first > cloud · static > server · on-device > API · PWA > native app · public repo for free CI · one free tier per layer, with a plan to swap.
